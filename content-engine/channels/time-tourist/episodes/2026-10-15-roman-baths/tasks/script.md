# Skill: write-script

You receive a task file with the channel, the series, its characters, the channel's learnings, the idea, and the
SKILL.md of every render skill the series uses. You write **one file: `script.json`**. Nothing else.

## How to write it

1. **Follow the series.** Use its beats, in order, with the same ids. Each beat's `purpose` says what it must do;
   `seconds` is a target — the voice decides the real timing.
2. **Hook first.** The first sentence of the first beat is ~5 words and lands within 2 seconds. Put the hook on
   screen too (`on_screen_text`, ≤ 30 characters works best). Questions and surprising claims work; greetings don't.
3. **Write for the ear.** Short sentences. Contractions. One idea per sentence. Numbers the way people say them.
   Read it out loud in your head at the character's speed. Total words are given in the task — stay inside them.
4. **Be the character.** Use its personality, vocabulary and verbal tics from its file. A catchphrase at most once.
5. **Show, don't decorate.** Every beat has a visual that explains what is being said (see the render skills).
6. **Facts are claims.** Every fact — spoken, on screen, in a part label, or a number in a graphic — goes into
   `claims` with a real source you have checked. Unverifiable → cut it. Confidence `low` → find a better source.
7. **Pronunciations.** If the voice may stumble (years, acronyms, names, symbols), add
   `"pronunciations": {"1938": "nineteen thirty-eight", "LED": "L E D"}`. Captions still show the original word.
8. **No AI-label text, no links, no "subscribe" unless the series' `cta` asks for it.**

## script.json (schema `script/v1`)

```jsonc
{
  "schema": "script/v1",
  "channel": "<channel slug>",            // must match the episode
  "series": "<series slug>",
  "idea": "<idea id>",
  "title": "<episode title>",
  "language": "en",
  "beats": [                               // the series' beats, same ids, same order
    {
      "id": "hook",
      "speaker": "<character name>",       // one of the series' characters
      "voiceover": "What's inside a bike bell?",
      "on_screen_text": "Inside a bike bell",   // optional, ≤ 48 chars, shown at the top
      "visual": { "skill": "render-3d-explainer", "shot": "establish" },  // a scene skill of the series, or {"skill": "none"}
      "character": { "placement": "full", "expression": "curious" }      // full | corner | hidden; expression from model.json
    }
    // …one object per series beat
  ],
  "visuals": {                             // shared data for scene skills (see each render skill)
    "render-3d-explainer": { "object": "bike bell", "parts": [ /* … */ ] }
  },
  "claims": [
    {
      "id": "c1",                          // c1, c2, …
      "claim": "A bicycle bell rings when a spring-loaded striker hits the dome.",
      "beat": "inside",                    // beat where it's said or shown
      "source": "https://… (or a precise citation)",
      "confidence": "high",                // high | medium | low
      "note": "optional: caveats, rounding, where sources disagree"
    }
  ],
  "pronunciations": {},
  "publish": {
    "title": "What's inside a bike bell?",
    "description": "1–3 sentences. No AI label here — the engine adds disclosure fields.",
    "hashtags": ["#howitworks", "#shorts"] // up to 5 is best (max 8)
  }
}
```

## Checks the engine runs (fix and re-run until clean)

- beats match the series exactly; speakers are series characters; expressions exist in the character's model.json
- each beat's `visual.skill` is one of the series' scene skills and its payload is valid
- `visuals[...]` payloads are valid for their skill (part ids unique, targets/callouts exist, sizes present …)
- every claim points at an existing beat
- estimated length is inside the series length; the first sentence fits the 2-second hook
- banned-topic keywords (warning; the QA review decides)

# Skill: render-storybook

A scene skill: during the beats that use it, it fills the frame with a square illustrated card (full width, from
y≈420 to y≈1500) and a title bar above it. You never draw pixels — you **describe scenes** from a fixed library of
settings, poses and props, and the skill draws them with wobbly hand-drawn lines, muted watercolour washes and paper
grain. Same script → same picture (fixed seeds), so re-renders are stable.

It suits stories told one picture at a time: a narrator character acting out a metaphor ("if you took one step
every…"), each sentence its own scene. Pair it with the `captions` skill and `caption_style: single-word` in the
series (one word at a time in the middle of the picture) and `skills.render: [render-storybook]` (no separate
character layer — the character lives inside the scenes).

## Title bar: `visuals["render-storybook"]`

```jsonc
{
  "title": "A billion seconds is how long?",  // 3–64 chars, shown on top for the whole video, upper-cased
  "highlight": ["billion seconds"]             // ≤ 4 parts of the title drawn in the channel's accent colour
}
```

Keep titles **≤ 30 characters** so they fit on one line at a readable size (longer titles wrap into two balanced
lines and get smaller). The title is on screen the whole time → its words and numbers are claims too.

## Each beat: `visual`

```jsonc
{
  "skill": "render-storybook",
  "scenes": [ /* 1–6 scenes, one per sentence of the beat's voiceover, in order */ ]
}
```

**Timing is automatic:** scene 1 starts with the beat, scene 2 with the beat's second sentence, and so on (a short
cross-fade between scenes). More scenes than sentences split the last sentence evenly. Fewer scenes than sentences
keep the last scene up. So write the voiceover in short sentences and give each one a picture.

### A scene

```jsonc
{
  "setting": "hills",        // hills | beach | sea | plain | desert | snow | night | space | room | city | rome | baths
  "time": "day",             // day | dusk | night   (night and space settings are always night)
  "camera": "push-in",       // still | push-in | pull-out | pan-left | pan-right   (slow move over the scene)
  "character": {             // the beat's speaker, posed in the scene; null = no character in this scene
    "pose": "point",         // stand | point | wave | think | shrug | cheer | hold | walk | sit | look-up | facepalm
    "x": 0.3,                // 0 = left edge … 1 = right edge (feet always on the ground)
    "scale": 1,              // 1 ≈ 37% of the picture's height; 0.3–2.5
    "facing": "right",       // left | right
    "expression": "curious", // a key from the character's model.json → expressions
    "hold": "clock",         // optional: cards | paper | book | clock | coins | drop | globe | sign | candle | phone
    "hold_text": "52!"       // optional: ≤ 12 chars written on a held sign / paper / book
  },
  "others": [                // ≤ 4 extra figures (same look, they don't talk) — crowds, "you", a friend
    { "pose": "stand", "x": 0.62, "scale": 0.8, "facing": "left" }
  ],
  "props": [                 // ≤ 8 props (below)
    { "type": "sign", "x": 0.72, "text": "1,000,000,000" }
  ]
}
```

Settings: `hills` rolling sage hills · `plain` flat grassland · `beach` sand, sea and a headland · `sea` open water
with a strip of shore · `desert` dunes · `snow` white hills · `night` hills under stars · `space` stars only ·
`room` wall, floor, window · `city` skyline behind a street · `rome` a Roman street with a temple and an arch ·
`baths` inside a Roman bathhouse (vaulted hall, columns, steaming pool; figures stand on the pool edge).

### Props

Every prop has `type`, `x` (0–1, its centre), optional `y` (0 = top … 1 = bottom), `scale` (0.2–4, default 1) and
`color` (hex). **Ground things** stand on the ground when `y` is left out; **sky things** float at a sensible
height. Some props use `text`, `count`, `content`, or `x2`/`y2`.

| prop | what it draws | uses |
|---|---|---|
| `sign` | wooden signpost with lettering | `text` (required) |
| `calendar` | wall/desk calendar page | `text` (required), e.g. "31 years" |
| `clock` | clock face with moving hands | `text` (optional: written on the face instead of hands, e.g. "0") |
| `paper` | a sheet of paper on the ground | `text` (small) |
| `book` | a book lying flat | `color` |
| `text` | big hand-lettered words or a number, outlined | `text` (required) |
| `speech` | speech bubble | `text` (required) |
| `thought` | thought cloud | `content` (globe, clock, question, cards, coins, sun, moon, planet, drop, money, heart, phone, satellite) or `text` |
| `question` | big "?" | — |
| `arrow` | curved arrow from (`x`,`y`) to (`x2`,`y2`) in the accent colour | `x2` (required), `y2`, `text` |
| `footprints` | trail of footprints from `x` to `x2` | `x2` (required), `y2`, `count` |

## Layout rules (read before placing anything)

- The picture is a 1000×1000 grid in scene units; the ground line is at about y = 830 (845–860 on beach, sea,
  room and city).
- **Caption band:** single-word captions appear at scene y ≈ 330–390, horizontally centred. Keep faces and
  lettering out of that band: standing characters at `scale` ≤ 1.2 (normal shots) or ≥ 1.9 (close-ups, the face is
  above the band) — scales in between put the caption across the face.
- Sky lettering (`text`, `speech`, `thought`) goes at y ≤ 0.28. Keep everything inside 0.05–0.95: the picture's
  edges are darkened by a vignette.
- One focal point per scene: the character plus 1–3 props. Leave air around the character.
- Every scene is a new picture: change the setting, the camera, the pose or the props from one sentence to the
  next. Escalate — the story's scenes should get bigger (one jar → a row of jars → the ocean).

## Writing for this skill

- The hook beat's first scene shows the number itself (`sign`, `text` or `calendar`) with the character reacting.
- Numbers on props are exactly the numbers in the voiceover ("1,000,000,000" ↔ "a billion"), rounded the same way.
- Every word on a prop (`text`, `hold_text`) and the title are on-screen text: factual ones need a claim with a
  source in `claims`, and the fact-check covers them.
- Short lettering: props ≤ 28 characters, held signs ≤ 12. Use digits with commas for big numbers.

## Checks the engine runs

`./engine make episode` rejects a script (and lists every problem) when: a scene uses an unknown setting/pose/prop,
an `arrow`/`footprints` has no `x2`, a `sign`/`calendar`/`speech`/`text` has no `text`, a beat has many more scenes
than sentences, or an `expression` isn't in the speaker's model.json.

# Skill: captions

Captions are generated, not written: you don't add anything to the script for them. They show the voiceover
exactly as written in `script.json` (so spelling and capitalisation there are what viewers read), a short page at a
time (≤ 2 lines), and highlight each word while it is spoken.

## How it works

- **Timings** come from the voice step (`audio/timings.json`). The local voice (Kokoro) predicts how long every
  phoneme lasts before generating audio; the engine reads those durations, so each word's start/end is exact — no
  speech recognition, no drift.
- **Pages** break at sentence ends and beat boundaries, and when a line would get too wide for the safe area.
- **Style** comes from the channel's brand: `font`, `accent_color` (highlight), `text_color`, `caption_case`
  (`upper` for ALL-CAPS captions). Captions sit in the lower part of the safe area, above platform UI.

## What this means for the script writer

- Write numbers and names the way they should appear on screen; add `pronunciations` if the voice should say
  them differently (`"1938": "nineteen thirty-eight"`).
- Very long words (14+ letters) get a line to themselves; prefer shorter words.
- Punctuation shows on screen. Use "—" and "…" sparingly; they also create pauses in the voice.

## QA

`workflows/qa.md` checks that caption words equal the script, the highlighted word matches the timings on ≥ 98 %
of frames, no word is shown over silence, and captions never leave the safe area or overflow.
